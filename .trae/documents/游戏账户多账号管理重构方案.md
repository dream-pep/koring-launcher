# 游戏账户多账号管理重构方案

## Summary

将「设置 → 游戏 → 游戏账户」页从「单账号 + 启动档案 + 登录方式」重构为**多账号列表页**：

- 一个账号一行，展示头像、昵称、UUID、登录类型
- 无账号时显示「请添加一个账号」空状态
- 右上角「添加账号」按钮，点击弹出 shadcn 风格弹窗（复用 `src/components/ui/modal.tsx`）
- 弹窗第一步选择账号类型：微软账号 / LittleSkin / 离线账户；**微软显示「暂时无法提供」不可选**，LittleSkin 与离线可完整登录
- 存储层从单账号升级为多账号 registry，并自动迁移旧版单账号文件
- 移除「启动档案」「登录方式」两个旧区块

## Current State Analysis

| 层 | 文件 | 现状 |
|---|---|---|
| 主进程存储 | `electron/auth.ts` | 单账号 `AuthData { username, uuid, accessToken, refreshToken, xboxProfile }`，文件 `koring-auth.json`；函数 `readAuth/writeAuth/deleteAuth` |
| 主进程认证 | `electron/core/auth.ts` | 已有 `offlineLogin`（MD5 推导 UUID）、微软 OAuth 系列；**无 LittleSkin** |
| IPC | `electron/handlers/auth.ts` | `auth:get` / `auth:save` / `auth:delete` / `auth:offline-login` |
| 前端 API | `src/api/auth-registry.ts` | `getAuth/saveAuth/deleteAuth` |
| 前端 Store | `src/stores/authStore.ts` | 单 `user: AuthResult`，action：`initFromRegistry/loginOffline/logout/...` |
| 启动流程依赖 | `src/stores/launchStore.ts#L38` | 读取 `useAuthStore.getState().user`（username/uuid/accessToken）——改造必须保留 `user` 字段 |
| UI 组件 | `src/components/ui/modal.tsx` | 项目内 shadcn 风格通用弹窗（`open/onClose/children/className`），已在 `CreateDialog`、`ModInstallDialog` 使用 |
| 页面 | `src/pages/setting/game/game-account.tsx` | 三区块：当前账号 / 启动档案 / 登录方式；使用 `SettingCard / SettingBadge / PageHeader / SectionTitle` |
| 设置组件库 | `src/components/setting/index.ts` | `SettingCard`、`SettingBadge`（variant: neutral/primary/success/warning/info/error/violet）、`SettingInput` 等 |
| LittleSkin | 全库无实现 | 需新写 Yggdrasil 登录 |

## Proposed Changes

### 1. 主进程多账号存储 `electron/auth.ts`

新增多账号数据结构（保留旧导出兼容）：

```ts
export type AccountType = 'offline' | 'microsoft' | 'littleskin';

export interface AuthAccount {
  id: string;            // crypto.randomUUID()
  type: AccountType;
  username: string;      // 游戏内昵称
  uuid: string;          // 带横线的 36 位 UUID
  accessToken?: string;  // LittleSkin / 微软令牌
  clientToken?: string;  // LittleSkin Yggdrasil clientToken
  avatarUrl?: string;    // 头像地址（可空，前端有兜底）
  addedAt: number;
  lastLoginAt: number;
}

export interface AuthStore {
  version: 2;
  activeAccountId: string | null;
  accounts: AuthAccount[];
}
```

新增函数（保留 `readAuth/writeAuth/deleteAuth` 旧函数不动，供其他未迁移调用）：

- `readAuthStore(): AuthStore` —— 读取；若文件为旧单账号格式（存在 `username` 且无 `version`），迁移为 `{ version: 2, accounts: [一条], activeAccountId }`（`accessToken` 非空 → `microsoft`，否则 `offline`），并**不立即写盘**（首次变更时落盘，避免只读场景写文件）
- `writeAuthStore(store: AuthStore): void`
- `upsertAccount(store, account): AuthStore`（同 `type + uuid` 视为同一账号，更新令牌与 `lastLoginAt`）
- `removeAccount(store, id): AuthStore`（若删除的是 active，则 active 回退到剩余第一个或 null）
- `setActiveAccount(store, id): AuthStore`

### 2. LittleSkin 登录 `electron/core/auth.ts`

新增 `littleskinLogin(username: string, password: string)`：

- 端点：`POST https://littleskin.cn/api/yggdrasil/authserver/authenticate`
- 请求体：`{ username, password, clientToken: <uuid>, agent: { name: 'Minecraft', version: 1 }, requestUser: false }`
- 成功：`{ accessToken, clientToken, availableProfiles: [{ id, name }], selectedProfile? }`
- 处理：
  - `availableProfiles` 为空 → 抛错「该账号没有可用的 Minecraft 角色」
  - 取 `selectedProfile ?? availableProfiles[0]`；`uuid` 将 32 位无横线 id 格式化为 36 位带横线
  - 返回 `{ username: profile.name, uuid, accessToken, clientToken }`
- 复用现有 `net.fetch` 风格与错误处理（HTTP 非 2xx 抛出中文错误：`LittleSkin 登录失败: <status>`，403 映射为「用户名或密码错误」）

### 3. IPC 扩展 `electron/handlers/auth.ts`

新增 handler（沿用 `{ success, data, error }` 返回约定）：

| 频道 | 入参 | 行为 |
|---|---|---|
| `auth:accounts-list` | — | 返回 `AuthStore`（含迁移后的账号列表） |
| `auth:account-add-offline` | `{ username }` | 校验 1–16 字符 → `offlineLogin` → upsert 账号（type=offline）→ 若当前无 active 则设为 active → 返回新 store |
| `auth:account-add-littleskin` | `{ username, password }` | `littleskinLogin` → upsert（type=littleskin，含 accessToken/clientToken/avatarUrl）→ 同上 → 返回新 store |
| `auth:account-remove` | `{ id }` | remove → 返回新 store |
| `auth:account-set-active` | `{ id }` | setActive → 返回新 store |

保留 `auth:offline-login`（兼容，不做删除）。写盘统一调用 `writeAuthStore`。

### 4. 前端 API `src/api/auth-registry.ts`

新增类型 `AccountType / AuthAccount / AuthStore`（与主进程同构）与函数：

```ts
listAccounts(): Promise<AuthStore>
addOfflineAccount(username: string): Promise<AuthStore>
addLittleskinAccount(username: string, password: string): Promise<AuthStore>
removeAccount(id: string): Promise<AuthStore>
setActiveAccount(id: string): Promise<AuthStore>
```

### 5. Store 改造 `src/stores/authStore.ts`

- 状态新增：`accounts: AuthAccount[]`、`activeAccountId: string | null`
- **保留 `user: AuthResult | null`**（由 active 账号映射：`{ username, uuid, accessToken }`），`launchStore` 无需改动
- action：
  - `initFromRegistry()` → `listAccounts()` 填充 accounts/active/user
  - `addOfflineAccount(username)` → 调 API → 用返回 store 更新状态
  - `addLittleskinAccount(username, password)` → 同上
  - `removeAccount(id)` / `setActiveAccount(id)` → 同上
  - `loginOffline/logout` 保留（内部改为调用新接口或保留旧逻辑不碍事；`logout` 语义调整为「移除当前账号」时由页面直接调 `removeAccount`）
- 统一 `loading`/`error` 处理，错误信息中文

### 6. 页面重构 `src/pages/setting/game/game-account.tsx`

结构调整：

```
PageHeader「游戏账户」（desc：管理 Minecraft 游戏内账户…）
  └ 标题行右侧：Button「添加账号」（Plus 图标）→ 打开 AddAccountDialog
  └ 账号列表（SettingCard 容器，每行一个账号）
       ├ 有账号：AccountRow × N
       │    左：头像 40×40（圆形，img 失败/为空 → 首字母或 UserRound 图标兜底）
       │    中：昵称（粗体） + 类型徽标 + UUID（font-mono 12px 截断）+ 最近登录时间
       │    右：当前账号标记（success 徽标「当前」） / 「设为当前」按钮 + 删除按钮（Trash2）
       │    交互：点击行 = 设为当前；删除需 ConfirmDialog 确认（复用 confirmDialogStore）
       └ 无账号：垂直居中空状态「请添加一个账号」（Gamepad2 图标 + 副文案）
```

- 类型徽标映射：`offline → neutral「离线账户」`、`littleskin → info「LittleSkin」`、`microsoft → primary「微软账户」`
- 移除「启动档案」「登录方式」两个 `SectionTitle` 区块及其相关旧代码（`ProfileRow`、`username` 输入、微软开发中卡片等）
- **不修改** `PageHeader` 外层与设置页布局约定（`src/pages/setting/index.tsx` 负责容器）

### 7. 新建添加账号弹窗 `src/pages/setting/game/AddAccountDialog.tsx`

使用 `Modal`（`src/components/ui/modal.tsx`），两步式（`step: 0 | 1`，`type: 'microsoft' | 'littleskin' | 'offline' | null`）：

- **Step 0 · 选择类型**：三个可选卡片（图标 + 标题 + 描述）
  - 微软账号：置灰不可点，右侧 `SettingBadge warning「暂时无法提供」`
  - LittleSkin：可点 → Step 1
  - 离线账户：可点 → Step 1
- **Step 1 · 填写表单**：
  - 离线：用户名输入（1–16 字符，Enter 提交）
  - LittleSkin：用户名 + 密码输入（password 类型）
  - 底部：「上一步」+「添加」（loading 时禁用并显示 Loader2）
  - 提交成功 → `toast.success` → 关闭弹窗并重置
  - 提交失败 → 弹窗内错误提示（红色文本 + AlertCircle）
- 关闭时（取消/遮罩/Esc）重置全部状态
- 弹窗宽度 `className="max-w-md"`，与项目现有弹窗风格一致

### 8. 头像来源决策

| 类型 | avatarUrl |
|---|---|
| littleskin | `https://littleskin.cn/avatar/player/{uuid}?size=64`（添加时由主进程写入 `avatarUrl`） |
| offline | `https://mc-heads.net/avatar/{uuid}/64`（渲染时由前端拼 UUID；加载失败 fallback 首字母圆形） |
| microsoft | 占位，使用 `xboxProfile.displayPicRaw`（当前 type 不可用，仅保留结构） |

统一兜底：`<img onError>` 切换为首字母圆圈（取 `username[0]` 大写）+ 渐变底色。

## Assumptions & Decisions

1. **多账号并存**：同 `type + uuid` 唯一；重复添加视为刷新令牌（upsert），不产生重复行
2. **LittleSkin 角色选择**：多角色时默认取 `selectedProfile`，否则第一个（不额外做角色选择 UI）
3. **LittleSkin 端点**：使用官方 `littleskin.cn`（不走镜像；若后续需要可再做配置）
4. **旧文件迁移**：只在读取时转换内存结构；任何写操作统一落盘为新格式 `version: 2`，旧数据不丢失
5. **`authStore.user` 兼容保留**，`launchStore` / 启动流程零改动
6. **删除区块不可逆**：`ProfileRow`、微软开发中卡片、正版验证方式卡片均随页面重构移除（用户已确认「只保留账号列表」）
7. **弹窗组件**：使用项目内 `@/components/ui/modal`（shadcn 风格），不引入 HeroUI Modal

## Verification

1. `pnpm build`（vite + tsc）通过，无类型错误
2. `pnpm dev` 手动验证清单：
   - 空状态：无账号时显示「请添加一个账号」
   - 添加离线账号：输入用户名 → 添加成功 → 列表出现一行（头像/UUID/「离线账户」徽标）
   - 重复添加同名离线账号 → 不新增行（upsert）
   - 添加 LittleSkin 账号：正确账号密码 → 出现一行（「LittleSkin」徽标）；错误密码 → 弹窗内提示错误
   - 多账号切换：点击行 → 「当前」标记迁移；刷新/重启后保持
   - 删除账号：确认弹窗 → 删除后 active 自动回退
   - 旧 `koring-auth.json`（单账号）启动 → 自动迁移为一行账号
   - 首页启动游戏 → 仍使用当前账号（`launchStore` 未受影响）
3. 边界：LittleSkin 无角色账号 → 提示「该账号没有可用的 Minecraft 角色」
